# 探究模式 · Interactive Inquiry

一个 DSH 模式预设：把"有变量可调、有结果可看"的概念，变成一个学习者**亲手操作**的任务。

**任务单位是单个交互任务，不是一门课。** 不建课程树、不排进度、不做题库。它是你在某个概念上"想亲手摸一下"时切进去的模式。

---

## 它和已有的东西有什么不同

| | 常见做法 | 探究模式 |
| --- | --- | --- |
| 产物 | 讲解 + 题目 | **一个可以拖的东西** + 一个必须回答的预测 |
| 学习机制 | 看讲解 → 做题 → 判分 | 预测 → 操作 → 观察 → **对质** → 自己说出规律 |
| 结束条件 | 答对 | **他用自己的话说出这个关系** |
| 判分 | LLM 或规则判分 | **不判分**——观察结果是事实，"算不算懂"由他说 |

市场上做"学习模式"的产品几乎都收敛到 **讲解 + 客观题 + 间隔重复**。本预设的差异化在**形态 A：亲手拖出直觉**（下面第 2 节），而不是再做一个刷题器。

---

## 安装

```bash
# 从 GitHub 安装（发布后）
dsh plugin --profile web add github:<你的ID>/dsh-inquiry-preset
```

本地开发时改为把仓库目录装成 bundle：`plugin_manager install_bundle`，`target` 传本仓库根的绝对路径。
装完**需要重启 DSH 宿主**，然后在新建会话的模式列表里选「探究模式」。

渲染依赖一个围栏渲染插件（提供 `dsh-ui` 围栏 → 真实组件的渲染）。已实测：

```bash
dsh plugin --profile web add @changfenhuang/dsh-genui
```

**它不是硬依赖。** 没有渲染器时围栏退回普通代码块，任务按 SKILL.md 里写好的降级路径继续成立（改问数值、列选项、手工算）。

---

## 怎么用

切到探究模式，说一个你想搞懂的关系：

> 我想搞懂阻尼振动里那个阻尼系数到底在干什么

它应该**先问你一个具体的、可证伪的预测**（"你猜 d 从 0.2 加到 1.5，波形会怎样？"），**然后**才把带滑块的东西给你，最后要你自己说出规律。

如果你发现它一上来就画图、或者直接开始讲解——那是 bug，不是设计。

## 设计要点

### 核心循环（`skills/inquiry-task/SKILL.md`）

**预测 → 操作 → 观察 → 对质 → 命名**

其中两条是硬性的：

- **没有预测就没有探究。** 要一个具体的、可证伪的预测，**并且要他说出来**——承诺感来自"在看结果之前必须表态"。说不出预测时，说明缺前置知识，应该回去讲最小必要的那一点，而不是硬给任务。
- **对质不能滑过去。** 猜错了要先问"你按什么推的"，针对那个推理修；直接讲正确结论等于把他刚暴露的错误模型又盖回去了。

### 四种任务形态

| 形态 | 往返 | 用途 |
| --- | --- | --- |
| **A 实时函数探究** | **零** | 旗舰。`plot` 组件自带参数滑块，拖动即时重绘 |
| **B 预计算族** | 零 | 离散/数据类：多序列图、标签页、可本地过滤的表 |
| **C 单点探针** | 一次 | 状态无法用表达式表达时，验证一个具体判断 |
| **D 本地自检** | 零 | 收尾专用，**不做主菜** |

形态 A 能零往返是因为渲染器的 `plot` 组件内建了参数滑块（`params` + 拖动即时重绘 + y 轴锁定 + `animateTo` 动画），不是我们实现的。

### 硬纪律（六条）

1. **绝不等待回合**——渲染完就结束回合，学习者的操作下一轮从正常输入框回来
2. **不剧透**——观察前任何地方不出现结论，包括组件标题和 `explanation` 字段
3. **围栏里只放可操作对象，教学文字放围栏外**（保证降级可读）
4. **没有渲染器就问数值**——降级路径必须始终存在
5. **不硬塞组件**——一段话能讲清就别画图
6. **先讲最小必要概念，再给任务**

`skills/inquiry-task/references/anti-patterns.md` 列了 8 个反模式，前两条（回合空转、剧透）是一票否决级。

### 为什么"不等待"是第一条

这是从一次真实的失败里学到的：**有人真做过交互式学习活动这条路，后来主动砍掉了整条链路**，理由是旧的 `Question → Reveal` 双工具结构"天然重复轮次，并让模型回合在等待用户期间一直处于运行状态"。

围栏是回答的一部分，不是工具调用。模型一旦"等"，回合就挂在运行中直到用户点一下——界面显示在思考，其实在发呆。所以：**渲染完就结束，把回答交还给普通输入框。**

## 目录

```
package.json                         dsh-inquiry-preset（bundle 根）
index.js                             入口桩：市场预检要求有入口文件才收
cordis.patch.yml                     预设声明（persona + 4 组子插件）
skills/inquiry-task/
├── SKILL.md                         核心循环 + 硬纪律
└── references/
    ├── task-shapes.md               四形态 + 表达式硬约束 + 降级路径
    └── anti-patterns.md             8 个反模式

tools/probe-skill-dir.mjs            技能被发现链路的逐环探针
VERIFICATION.md                      实测证据
```

排查"技能没出现"时先跑探针——这条链路上任何一环断了都是**静默**的（路径错返回空列表、frontmatter 不合规只打一条 warn）：

```bash
node tools/probe-skill-dir.mjs      # 退出码 0 = 全通过
```

### 两个不能动的约束（改包时容易踩）

1. **不要给 `package.json` 加 `exports` 字段。** 技能目录路径靠
   `createRequire(baseUrl).resolve('dsh-inquiry-preset/package.json')` 解析，而 `exports` 一旦存在，
   子路径访问默认被封锁，会抛 `ERR_PACKAGE_PATH_NOT_EXPORTED`——表现是**技能静默消失**。
   若确实要加，必须同时显式导出 `"./package.json": "./package.json"`。
2. **不要删 `index.js`。** 它从未被 import，但市场装前预检会从包根解析入口文件
   （`exports["."]` → `main` → 兜底 `index.js`），拿不到就判"缺入口文件"并拒收。
