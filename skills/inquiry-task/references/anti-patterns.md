# 反模式：这个产品最容易怎么坏

按危害排序。前两条会直接让产品不成立，不是"体验差一点"。

## 1. 回合空转（最严重）

**症状**：你渲染了围栏，然后停下来等学习者操作。

**为什么致命**：围栏是回答的一部分，不是工具调用。你一旦"等"，模型回合就挂在运行中，直到他点一下才继续——界面显示你在思考，其实你在发呆。**先前有人真做过这条路，后来主动砍掉了整条交互活动链路**，理由就是这个：旧的 `Question → Reveal` 双工具结构"天然重复轮次，并让模型回合在等待用户期间一直处于运行状态"。

**正确做法**：渲染完就结束回合。他的操作下一轮通过正常输入框或围栏 action 回来，**当成一条新的用户消息处理**。

**唯一的例外**：如果某个控件确实必须拿到值才能继续，就**不要用控件**——用普通文字问，让他打字回答。

## 2. 剧透

**症状**：在他观察之前，回答里已经出现了结论。

泄漏的形态比想象的隐蔽：

- 直接说："你会发现峰值变窄了" ← 那他还预测什么
- 暗示方向："注意看**变窄**的时候……" 
- 标题泄底：`"title":"阻尼越大衰减越快"` ← 标题也是正文
- 组件字段泄底：`radio` 的 `explanation`、`quiz` 的 `feedback`、写在选项里的提示
- 教学计划泄底："下一步我们来……"

**正确做法**：围栏里的标题、标签、说明只描述**将要发生什么**，不描述**结果是什么**。用 `"title":"阻尼系数对波形的影响"` 而不是 `"title":"阻尼越大衰减越快"`。

## 3. 玩具化

**症状**：给了一个能拖的东西，但他只是在玩，没有学到关系。

三个成因，逐个对治：

- **他没先预测就让他动手** → 补上这一步：要一个具体的、可证伪的预测，并且要他说出来。这是最重要的一条，见 SKILL.md 第 1 步。
- **参数太多** → 一次一个。两个参数时他无法归因。
- **拖动范围不覆盖翻转点** → 全程单调变化时没有可预测的东西。**发布前自己估一遍范围**，确保存在一个"定性改变"的位置。

## 4. 组件展览

**症状**：一段话能讲清的事，堆了五张卡片两个图表。

渲染器有自己的版面纪律（默认无卡、焦点唯一、层级靠字不靠框）。**遵它**。判据很简单：**把围栏整块删掉，这段回答还读得通吗？** 读不通说明你在用组件替代思考。

## 5. 把自检当主菜

**症状**：一上来就出题。`quiz` 判分很爽、零往返、实现简单，于是很容易变成"套了个 UI 的刷题器"。

**这是所有同类产品的公共区**——客观题、题库、间隔重复，市场上至少有十个成熟产品。**你的差异化在形态 A（亲手拖出直觉），不在形态 D。** 自检只在探究做完之后用来确认一次。

## 6. 缺前置时硬给任务

**症状**：他连预测都说不出来，你还是把滑块递过去了。

结果是他瞎拖一通，看着热闹，什么也没建立。**"说不出预测"是缺前置的信号，不是需要更多交互的信号。** 这时候回去讲最小必要的那一点，讲完再来。

## 7. 对质滑过去

**症状**：他猜错了，你直接讲正确结论。

那他刚暴露出来的错误模型就又被盖回去了——下次还会错。**先问"你刚才是按什么推的"**，针对那个推理修。这个差就是这堂课，不要跳。

## 8. 任务后自动续摊

**症状**：任务做完，你顺手开始下一个知识点、总结整章、给学习建议。

**停。** 结束条件是他自己说出规律。说完就收，可以问一句要不要继续，但把决定权交回去。自动续摊会让他觉得这是一门课，而你的产品单位是**一个任务**。
