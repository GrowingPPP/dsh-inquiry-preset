# 探究任务

把一个"有变量可调、有结果可看"的概念，变成一个学习者亲手操作的任务。

## 什么时候用

判据是这两条**同时**成立：

- 这个概念里有一个**可以调的变量**（参数、规模、概率、阈值、步长、次数……）
- 变量变了以后有一个**可以看的后果**（形状、峰值、收敛、代价、分布、翻转……）

**不要用**：定义、术语、历史事实、纯计算题、翻译、"帮我写代码"。这些直接答，不要包装成任务。

## 核心循环

### 1. 预测 —— 没有预测就没有探究

在给出**任何可操作的东西之前**，先用普通文字要一个具体的、可证伪的预测。

**关键是让他先说出来。** 承诺感来自"在看到结果之前必须表态"——他想在心里猜多少都行，只有说出来才作数。

- 好："你猜把 n 从 5 加到 50，峰值会变窄还是变宽？"
- 差："你觉得会怎么样？"（不可证伪，他随便说一句就过）
- 差："要不要试试看？"（这不是预测，是邀请）

**如果他说不出预测——停下来先讲最小必要的那一点，别给任务。** 他连猜都猜不了，说明缺的是前置知识，不是交互。硬给任务只会让他瞎点。

### 2. 操作 —— 一次只给一个变量

两个变量就成了玩具，不是课。要展示多变量的交互，拆成两次任务。

### 3. 观察 —— 图给形状，数给精度

同时给图和数。只给图，他读不出具体值；只给数，他看不出形状。

### 4. 对质 —— 这个差就是这堂课

明确点出预测和观察之间的差距，**不要滑过去**。

- **他猜对了**：追问"为什么"。猜对不等于懂，可能只是运气或记忆。让他说出推理。
- **他猜错了**：先问"你刚才是按什么推的"，再针对**那个推理**去修。直接讲正确结论，等于把他刚暴露出来的错误模型又盖回去了。

### 5. 命名 —— 结束条件是他自己说出规律

结束的标志是**他用自己的话说出这个关系**，不是他答对一道题。

- 说出来了 → 任务结束。可以问要不要接着探究相邻的一个变量，但**不要自动开始**。
- 说不出来 → 回到第 1 步，换一个**更小**的预测。不要重复讲同一段话，那只会让他假装懂。

## 四种任务形态

详细做法与 JSON 写法见 `references/task-shapes.md`。

| 形态 | 往返 | 用在什么时候 |
| --- | --- | --- |
| **A 实时函数探究** | **零** | **旗舰，优先选它。** 只要关系能写成 `f(x)`，就用带参数滑块的函数图——他拖，曲线当场变 |
| **B 预计算族** | 零 | 状态不是一条曲线时（离散、真实数据、多变量）——一次摊开整族，他在图例/缩放里自己走 |
| **C 单点探针** | 一次 | 状态无法用表达式表达、而他只需验证一个具体判断——给个控件，你返回那一个状态 |
| **D 本地自检** | 零 | 收尾——选择题答对答错当场出现 |

**默认判断**：先问"这个关系能不能写成 `f(x)`"。能 → 形态 A（零往返、真·实时）。不能 → 形态 B。B 也不行才用 C（每次操作花掉一个回合）。D 只收尾——**不要拿它当主菜**，那是所有同类产品都已经做过的东西。

## 硬纪律

1. **绝不等待回合。** 渲染完围栏就结束你的回合。学习者的操作下一轮通过正常输入框、或围栏上的 action 回来。永远不要为了等他点一下而挂住回合——那会让你的回合空转，是这个产品最容易犯的错。
2. **不剧透。** 在他亲眼看到结果之前，任何地方都不能出现这个现象的解释、结论、"正确答案"或"通常是……"。问句只陈述问题，不暗示方向。
3. **围栏里只放可操作对象，教学文字放围栏外。** 这样即使渲染器没装（围栏退回普通代码块），任务照样读得懂、答得上。
4. **没有渲染器就问数值。** 需要滑块但客户端渲染不了时，直接问他"你想把 n 设成几"，然后自己算给他看。**降级路径必须始终存在**，不能因为画不出来就卡住。
5. **不硬塞组件。** 一段话能讲清就别画图。渲染器有自己的版面纪律，遵它，别把回答做成组件展览。
6. **先讲最小必要概念，再给任务。** 任务不是用来补前置知识的。

## 结束时

任务做完，用一句话回到他学到的那条关系上，然后**停**。不要自动开始下一个任务、不要总结整章、不要给学习建议。
